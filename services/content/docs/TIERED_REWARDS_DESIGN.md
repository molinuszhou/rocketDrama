# JoyeDrama 分层激励设计

## 目标

奖励系统应让用户能够清楚理解“完成什么、得到什么、何时到账”。默认任务进度只由有效完成的剧集观看事件累积；广告不作为独立任务次数或奖励来源。激励广告仅承担两类可选作用：解锁锁定分集，或将已经达成的任务/签到奖励翻倍。

| 奖励层 | 当前实现范围 | 服务端状态 | 用户可见行为 |
|---|---|---|---|
| 看剧阶梯奖励 | 多个 `watch_episode` 任务，例如完整观看 1、3、5 集 | 已实现，可通过版本化规则 JSON 修改目标、金币和翻倍开关 | 完成有效剧集观看后出现领取按钮；可选择广告翻倍（如规则开启） |
| 连续签到奖励 | 7 日及以上阶梯金币数组 | 已实现，可通过规则 JSON 修改数组、连续规则和翻倍开关 | 每日直接领取；如规则开启，可完整观看激励广告后领取双倍 |
| 活动奖励 | 活动名称、任务说明、进度示意和点数 | 仅 Android UI 演示，暂不写入账本或发放点数 | 显示“即将开放/活动演示”，不承诺可领取或可提现 |
| 锁集解锁 | 每次激励广告解锁的集数和每日上限 | 已实现；服务端可结算时会持久化权益 | 广告完整观看后优先服务端结算；服务端不可达时只作本次播放会话解锁，不记金币或活动点数 |

## 配置原则

运营人员只能将正式看剧任务定义为 `watch_episode`。建议每个规则版本至少提供两个可达到的阶梯，例如 1、3、5 集；单项金币、领取上限、免费集数、广告解锁上限和广告翻倍开关均由服务端规则 JSON 管理。规则变更必须更新 `version`，以便账本审计。

## 失败降级

在开发和试运营阶段，Pangle 激励广告完整回调代表用户已经完成广告观看。若奖励服务正常，客户端先获取一次性广告权益令牌，再进行服务端锁集解锁或翻倍结算。若奖励服务无地址、网络不可达、令牌签发失败或结算失败，客户端仍调用合作方播放器的当前会话解锁回调，以避免用户看完广告却不能继续播放；同时明确提示“本次已解锁，奖励未到账，待服务恢复后再参与奖励活动”。该临时播放解锁不写入本地永久权益，也不发放金币或点数。

生产环境应使用服务端广告回调/验签，补充可靠的用户身份和可验证播放事件；临时本地会话解锁不能作为长期权益结算依据。
