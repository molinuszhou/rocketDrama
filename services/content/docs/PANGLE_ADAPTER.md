# Pangle 内容适配边界

## 当前状态

本服务端已包含 `PangleDramaProvider`，但它默认禁用且不返回真实剧集、封面、播放地址或虚构权益。这样做是为了避免把广告测试 App ID/广告位误当成内容授权，或在未取得内容 SDK 和地区授权时向客户端伪造可播放内容。

Pangle 的广告 SDK 与短剧内容合作应被视作两条独立链路。当前的 Pangle 广告测试参数仅用于 Android 广告实验室；它们不会被此服务端作为 Pangle 内容凭据读取。

## 服务端与 Android 的责任分配

| 事项 | 服务端 | Android 客户端 |
| --- | --- | --- |
| 内容是否在用户地区可见 | 根据内容合作方返回的地区、语言、合同期和下架状态过滤。 | 仅渲染服务端或 SDK 允许展示的条目。 |
| 统一卡片与运营排序 | 将获授权的 Pangle 元数据映射为 `DramaCard`，与自由剧交错排序。 | 使用统一 Feed 组件显示来源标识。 |
| 播放 | 返回 `playbackMode = PANGLE_SDK` 与受控 `sdk_route`。 | 调用合作方提供的内容 SDK/Fragment/Activity；不解析或转发私有播放 URL。 |
| 解锁权益 | 接收并保存经合作方规则验证的最终状态；不得用广告客户端事件伪造状态。 | 按 SDK 的广告解锁和回调逻辑执行。 |
| 广告变现 | 维持 Pangle 广告 SDK 的测试/生产配置。 | 展示对应广告，生产环境通过服务端回调或合作方规定的链路完成确认。 |

## 启用前必须取得的资料

1. Pangle 内容产品/短剧内容 SDK 的正式合作确认，且明确覆盖目标国家或地区。
2. 内容应用 ID、SDK/AAR 或 Maven 坐标、Android Demo、初始化方法和版本兼容矩阵。
3. 面向测试包名与生产包名的配置文件，以及平台要求的内容授权/应用资质。
4. 可使用的片单/分集元数据接口或 SDK 回调说明，包含下架、刷新和地区过滤机制。
5. 播放、试看、激励解锁、解锁回调、异常处理及服务端验证规则。
6. 数据处理条款、内容版权链路、投放地区和有效期。对于中国内地以外市场，必须明确合作方是否允许目标地区分发。

## 接入步骤

1. 在环境变量中保留 `PANGLE_CONTENT_ENABLED=false`，直到上述资料齐备。
2. 用合作方数据实现 `PangleDramaProvider.list_dramas`、`get_drama` 和 `get_episode`。元数据应尽量由合作方实时刷新，避免长期缓存下架内容。
3. 所有 Pangle 分集返回 `PlaybackMode.PANGLE_SDK`，而不是普通签名 URL。
4. Android 收到 `sdk_route = pangle_content_sdk` 后交给合作方 SDK；自由剧仍通过 `SIGNED_URL` 播放。
5. 只有在平台权益确认后，服务端才写入已解锁状态；不要用客户端按钮点击或广告展示事件直接发放内容权益。
6. 在 `GET /v1/providers/health` 变为健康后，逐区域打开 Feed 流量并记录播放、错误、解锁和下架事件。
