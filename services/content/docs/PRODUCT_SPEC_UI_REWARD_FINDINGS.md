# JoyeDrama 策划书：UI 与动态激励实现要点

## 采用范围与边界

本文件只提炼用户体验结构和动态配置原则，不继承策划书中的产品名、包名、第三方品牌资产或未经线上验证的金额/阈值。所有奖励金额、任务目标、广告频控、提现档位和渠道均必须由服务端返回，不得写死在 Android 客户端。

## 统一信息架构

客户端应采用四个明确功能入口：**首页、发现、任务、我的**。内容来源是内部实现，不在用户界面暴露。当前没有自有剧时，首页和发现仅展示可用的外部短剧；后续自有剧加入时统一混排。

| 入口 | 参考结构 | 本轮实施优先级 |
|---|---|---|
| 首页 | 深色内容货架、余额/任务引导、分类、Banner、继续观看、横向精选/热门/最新内容行。 | 高 |
| 发现 | 全屏竖向播放流、标题叠层、圆环进度、奖励反馈与提现引导。 | 后续，先预留状态模型。 |
| 任务 | 签到、可完成/进行中/可领取任务、普通领取与广告翻倍。 | 高 |
| 我的 | 钱包摘要、继续观看、收藏、历史、设置。 | 高 |

## 播放和锁集体验

播放器继续使用合作方 PSSDK 处理视频渲染、播放鉴权和内容授权；JoyeDrama 提供统一的视觉外壳。锁集应显示剧封、集数、剧名、明确的“观看广告解锁”动作和可选的奖励说明。锁定起始集、一次广告解锁集数、广告解锁次数和奖励金额必须来自服务端规则。

## 激励、任务和钱包的动态原则

| 领域 | 客户端职责 | 服务端职责 |
|---|---|---|
| 激励解锁 | 展示规则文案，调用 Pangle 激励广告，提交广告完成证明，执行已确认的解锁结果。 | 决定锁集、免费集数、一次解锁范围、每日上限、奖励和权益有效期。 |
| 任务 | 展示任务卡、进度、领取、广告翻倍入口和反馈。 | 下发任务列表、目标、奖励、资格、任务开关、每日次数和结算结果。 |
| 签到 | 展示连续签到状态和普通/广告翻倍领取。 | 判定日期、补签、连续规则、奖励、翻倍次数和风控。 |
| 观看奖励/圆环 | 显示进度与领取动作。 | 用可信观看事件计算时长/集数、周期、奖励与冷却。 |
| 现金/金币钱包 | 只显示服务器确认的余额、记录、兑换/提现资格。 | 保存不可篡改账本、提现档位、地区渠道、条件和人工/自动风控状态。 |
| 广告频控 | 依据配置决定是否请求广告，并显示不可用原因。 | 下发按国家、版本、实验、人群、广告类型的频率与阈值。 |

## 本轮后端最小可用范围

1. `GET /v1/rewards/bootstrap`：返回版本化激励规则、任务列表、钱包摘要、今日上限和 UI 文案。
2. `POST /v1/rewards/events`：接收可信客户端事件（广告完成、有效观看、签到、领取），由服务端完成幂等结算。
3. `POST /v1/rewards/claim`：领取任务、签到或圆环奖励；支持普通领取或激励翻倍，但只有完成广告证明后才允许翻倍。
4. `GET /v1/rewards/ledger`：返回用户的可审计奖励流水。
5. 规则存储使用版本化 JSON 文件作为开发环境后端配置源；未来可切换数据库/运营后台，不改变 Android API 契约。

## 安全与合规要求

用户权益、现金、金币、任务完成和提现资格不能仅凭客户端状态确定。广告奖励只有在 SDK 成功回调且服务端验证请求幂等性、用户身份、广告类型、规则版本和频率后才结算。当前开发包可用匿名设备 ID 演示；生产环境必须使用服务端签发的用户会话与服务端广告回调/验签。不得将激励设计为不可解释或无法达到的“差一点”机制；所有规则须向用户明确展示、可由运营调整且满足适用法律和广告平台政策。
