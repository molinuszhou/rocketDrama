# JoyeDrama 独立奖励与广告结算服务架构

**版本：0.8.0（v8 奖励预授权与播放器体验规则）**
**状态：开发实现基线**
**运行边界：独立于自有短剧内容服务，使用 PostgreSQL 持久化用户奖励、广告事件、权益和运营规则。**

## 目标与边界

奖励服务仅处理宝石、钱包余额、可提现余额、签到、随机宝箱、逐集待领取奖励、皇冠成长、广告事件与解锁权益。它不读取视频文件、不签发播放 URL，也不管理剧集目录；目录、媒体文件和本地播放会话仍由独立 content service 负责。

> 客户端只能上报用户标识、广告位、幂等请求标识和必要播放事件。**宝石金额、随机结果、皇冠倍率、广告频控与余额变动均由服务端事务计算并写入 PostgreSQL。**

## 业务规则

| 项目 | 当前服务端规则 |
|---|---|
| 业务日 | 使用 `Asia/Shanghai` 的自然日。每日宝箱按业务日生成，不依赖后台定时清零。 |
| 前三集 | `free_episodes_count=3`。第 4 集起，客户端先弹出确认；用户确认并完整观看 `rv_episode_pass` 激励广告后，才调用 content service 解锁并自动播放。 |
| 有效观看 | 一个用户、一个分集只生成一次待领取宝石。宝石不在完播时自动入账。 |
| 皇冠倍率 | 当前最高皇冠等级会作用于未来新生成的单集待领取宝石。新手为 `1.00x`，默认皇冠为 `2.00x`；每级倍率可在后台调整。 |
| 悬浮球领取 | 用户完整观看 `rv_episode_rewards_claim` 激励广告后，消费该 `ad_event_id` 调用 `POST /v2/episode-rewards/claim-all` 一次性领取全部积累的单集宝石。已预翻倍分集按双倍结算。 |
| 本集翻倍 | 用户可在分集播放中、完播奖励尚未生成前，完整观看一次 `rv_episode_reward_boost` 激励广告预先开启翻倍。完播后该集待领取宝石自动按双倍生成；每集最多一次。 |
| 随机宝箱 | 每日自动生成指定数量的宝箱；每累计指定数量的有效观看分集再生成一只。每只宝箱均需完整观看一条 `rv_random_chest_open` 激励广告，服务端以安全随机数在最小/最大宝石区间内结算。库存可连续开启。 |
| 欢迎与签到 | 欢迎奖励由 `rv_welcome_bonus` 激励广告结算；每日签到由 `rv_checkin_complete` 激励广告结算。已签到用户再次打开连续签到奖励时，客户端引导观看激励广告开启随机宝箱；若广告完整观看后库存已为空，服务端拒绝结算并由客户端明确提示。 |
| 剧中、拖拽与倍速插屏 | 客户端按快照中 `mid_episode_*`、`seek_*` 与 `speed_*` 规则请求广告。每集剧中广告、每次拖拽广告和每次调整倍速广告均独立记录、限额和恢复原播放进度；设为 `0` 表示后台不设置小时上限。 |
| 皇冠与钱包 | 皇冠成长默认每完整观看 `2` 段激励广告完成一次成长加速，广告数量可配置；等级同时决定后续单集宝石倍率。宝石兑换后进入**钱包余额**，再按服务端日规则转入**可提现余额**。广告加速按当日基础可转入金额的可配置百分比计算，快照返回预计明日与本次广告可额外转入金额，默认不限制每日次数。 |
| 提现 | 仅提供余额与资格预检。`withdrawal_enabled=false` 时返回明确禁用状态；不执行支付，不伪造到账。 |

## HTTP 接口

| 方法与路径 | 用途 |
|---|---|
| `POST /v2/bootstrap` | 返回钱包、签到、随机宝箱库存、逐集待领取宝石、皇冠进度、解锁提示和全部广告策略快照。 |
| `POST /v2/watch-events` | 上报有效观看并生成该集待领取宝石；每累计指定集数时生成追剧随机宝箱。 |
| `POST /v2/ads/rewarded/complete` | 记录完整激励广告；处理欢迎奖励、签到、锁集解锁、全量领取授权、本集预翻倍、随机宝箱开启、皇冠广告升级和钱包广告加速。必须携带唯一 `ad_event_id`。 |
| `POST /v2/episode-rewards/claim-all` | 消费 `rv_episode_rewards_claim` 产生的未使用 `ad_event_id`，一次领取所有待领取分集宝石。 |
| `POST /v2/interstitials/shown` | 记录剧中、拖拽、倍速或暂停等被动插屏展示，用于独立频控。 |
| `POST /v2/checkins` | 旧客户端兼容端点；v7 会明确拒绝直接签到并要求 `rv_checkin_complete`。 |
| `POST /v2/withdrawals/preflight` | 返回透明的提现资格、余额与当前禁用原因；不执行支付。 |
| `GET /v2/admin/policy` | 读取随机宝箱、广告规则和皇冠倍率。需要 `Authorization: Bearer ADMIN_DASHBOARD_TOKEN`。 |
| `PUT /v2/admin/policy/operating` | 更新随机宝箱区间、每日/追剧产箱数量、剧中/拖拽/倍速插屏、皇冠成长广告数量和钱包广告加速比例/上限。需要管理员令牌。 |
| `PUT /v2/admin/crown-multiplier` | 更新指定皇冠等级的未来单集宝石倍率。需要管理员令牌。 |
| `GET /admin` | 本机运营后台页面；令牌只在浏览器会话请求头中使用。 |
| `GET /health` | 检查数据库连接和服务状态。 |

## 表结构概览

| 表 | 责任 |
|---|---|
| `users` | 用户宝石、钱包余额、可提现余额、活跃日与签到状态。 |
| `daily_counters` | 每日激励广告、有效观看、插屏计数和每日宝箱发放状态。 |
| `rewarded_ad_events` | 激励广告唯一事件、广告位、处理结果与幂等保护。 |
| `watch_events` | 有效观看事件与分集标识；每用户每分集只记录一次。 |
| `episode_reward_claims` | 每集待领取宝石、预翻倍和领取状态。 |
| `random_chest_inventory` | 每只随机宝箱的来源、业务日、库存状态和已结算金额。 |
| `checkins` | 每日签到及基础宝石。 |
| `achievement_policy` | 五级皇冠条件、一次性宝石奖励和单集宝石倍率。 |
| `user_achievements` | 用户皇冠等级达成与一次性结算状态。 |
| `interstitial_events` | 剧中、拖拽、倍速、暂停等被动插屏展示记录。 |
| `ledger_entries` | 不可变宝石、钱包余额和可提现余额变动账本。 |
| `reward_policy` | 随机宝箱、广告频控、钱包转入和其他运营规则。 |
| `reward_policy_admin_audit` | 管理员规则与皇冠倍率调整的审计记录。 |
| `schema_migrations` | 运行时增量迁移版本标记，避免重放旧约束 SQL。 |

## 广告安全边界

当前 Debug 版本允许 Android 传入明确的开发测试证明。生产环境必须接入广告平台服务端回调或可验证签名后，才允许把 `verified=true` 的广告事件写入奖励账本。客户端回调、广告位名或设备标识本身不能作为生产发奖依据。

## 客户端交互约束

| 场景 | 实现约束 |
|---|---|
| 广告期间播放器 | 展示任何全屏广告前保存播放状态并调用 `ExoPlayer.pause()`；广告关闭后仅恢复广告前正在播放的分集。 |
| 剧中与拖拽广告 | 广告关闭、跳过或无填充后都必须恢复原播放进度或执行目标拖拽，不能卡住控制条。 |
| 下一集解锁 | 免费集自动续播；锁集仅在用户确认后请求激励广告。奖励服务结算与内容解锁成功后自动播放目标集。 |
| 悬浮球 | 聚合所有待领取宝石；领取一次先完整观看激励广告，再消费广告授权一次性结算，领取操作保持服务端幂等。 |
| 随机宝箱 | 每次只开启一只；广告完整观看后才由服务端扣减库存并随机结算。 |
