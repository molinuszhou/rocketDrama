# DramaFlow 独立积分与广告结算服务架构

**版本：0.4.0（v4 奖励规则）**
**状态：开发实现基线**
**运行边界：独立于自制短剧内容服务，使用 PostgreSQL 持久化状态。**

## 目标

该服务仅处理用户宝石积分、现金钱包换算、签到、宝箱、五级皇冠成长、逐集待领取宝石、十集追剧加奖、激励广告完成事件、插屏频控状态与自有剧解锁权益。它不读取视频文件、不签发媒体 URL，也不管理剧目目录；所有视频目录、播放会话和媒体资产仍由独立内容服务负责。

> 客户端仅上报用户标识、广告位、幂等请求标识和必要的播放事件。**宝石金额、日频控、轮次、现金钱包和权益均由服务端事务计算并写入 PostgreSQL。**

## 数据与业务规则

| 项目 | 数据库规则 |
|---|---|
| 日周期 | 以 `Asia/Shanghai` 的自然日为业务日，不依赖后台定时清零任务；查询和写入按业务日分区。 |
| 宝石 | `gems_balance` 为非负整数，所有变动写入不可变 `ledger_entries`。 |
| 汇率 | 默认每 `150,000` 宝石换算为 `$1.00` 现金钱包；以整数微美元存储，避免浮点误差。 |
| 前三集 | 仅根据服务端下发给客户端的 `free_episodes_count=3` 做广告豁免展示；内容服务实际权益仍以自身规则为准。 |
| 集间 RV | 从第 4 集起，客户端仅在用户主动确认后调用 `POST /v2/ads/rewarded/complete`；广告完整关闭后向内容服务请求本集解锁并自动续播。该广告只提供内容通行权益。 |
| 有效观看 | 客户端在该集达到最短有效观看阈值后调用 `POST /v2/watch-events`；每个用户、每个分集仅生成一笔待领取基础宝石，不自动记入钱包。 |
| 单集领取与翻倍 | 用户调用 `POST /v2/episode-rewards/claim` 后基础宝石进入钱包；用户可主动观看一次 `rv_episode_reward_double` 广告获得同额翻倍宝石。 |
| 十集追剧加奖 | 每累计 10 集有效观看生成一笔额外宝石。用户调用 `POST /v2/ten-round-rewards/claim` 直接领取基础奖励；之后可主动观看一次 `rv_double_reward` 广告获得同额翻倍宝石。额外奖励遵循 `R(n)=max(R0×n^-α,floor)`。 |
| 签到 | 每个业务日仅一次基础签到；D1–D30 阶梯由数据库种子初始化。签到完成后可完整观看一次 RV 获得等额双倍奖励。 |
| 宝箱 | 当日已签到且未领取过宝箱时，完整观看 RV 后结算 2,000 宝石。 |
| 皇冠之路 | 在有效观看、签到或激励广告事件写入时，事务内计算青铜、白银、黄金、钻石、皇冠五级累计条件；每级仅结算一次并自动发放对应宝石。 |
| 插屏 | 插屏展示事件记录至数据库；客户端以服务端快照中的 90 秒冷却、每小时 3 次及 RV 重置时间为准。插屏展示时必须暂停本地播放器，关闭后再按用户原状态恢复。 |
| 提现 | 仅提供余额与资格预检接口。`withdrawal_enabled=false` 时返回明确不可提现状态；不制造不可达门槛或虚假到账。 |

## HTTP 接口

| 方法与路径 | 用途 |
|---|---|
| `POST /v2/bootstrap` | 获取钱包、签到、宝箱、成就、待领奖励、解锁提示和插屏频控快照。 |
| `POST /v2/ads/rewarded/complete` | 记录完整激励广告；处理集间通行、领奖、翻倍、宝箱和签到翻倍。请求必须携带唯一 `ad_event_id`。 |
| `POST /v2/watch-events` | 上报有效观看事件并生成该集待领取宝石；请求必须携带唯一 `event_id`。 |
| `POST /v2/episode-rewards/claim` | 领取指定分集的基础宝石，不需要广告。 |
| `POST /v2/ten-round-rewards/claim` | 领取指定累计十集轮次的额外基础宝石，不需要广告。 |
| `GET /admin` | 本机运营后台页面；需要管理员令牌才可读取或保存规则。 |
| `GET /v2/admin/policy`、`PUT /v2/admin/policy/damping` | 读取或调整十集追剧加奖的阻尼系数；使用 `Authorization: Bearer ADMIN_DASHBOARD_TOKEN`。 |
| `POST /v2/checkins` | 完成基础签到并返回当天的基础奖励；不依赖广告。 |
| `POST /v2/interstitials/shown` | 记录插屏展示，供小时频控与冷却判定使用。 |
| `POST /v2/withdrawals/preflight` | 返回透明的提现资格、余额和当前禁用原因；不执行支付。 |
| `GET /health` | 仅检查数据库连接和服务状态。 |

## 表结构概览

| 表 | 责任 |
|---|---|
| `users` | 用户余额、当前签到状态与业务日统计。 |
| `daily_counters` | 每日 RV、观看集数、完成轮次、已领奖励轮次与插屏次数。 |
| `rewarded_ad_events` | 激励广告的唯一事件、广告位、处理结果和幂等保护。 |
| `watch_events` | 有效观看事件与分集标识；每个用户、分集只记录一次。 |
| `episode_reward_claims` | 每集待领取基础宝石及领取/广告翻倍状态。 |
| `pending_claims` | 累计十集追剧加奖及领取/广告翻倍状态；旧版数据标记为 `LEGACY`。 |
| `checkins` | 每日签到、基础宝石和翻倍宝石。 |
| `chest_claims` | 每日宝箱领取记录。 |
| `user_achievements` | 皇冠等级与一次性结算状态。 |
| `interstitial_events` | 插屏展示时间，用于服务端频控。 |
| `ledger_entries` | 不可变宝石与现金钱包变动账本。 |
| `reward_policy` | 奖励规则与十集加奖阻尼系数。 |
| `reward_policy_admin_audit` | 阻尼系数后台调整的审计记录。 |

## 广告安全边界

当前 Debug 版本允许由 Android 传入明确的开发测试证明；生产环境必须接入广告平台服务端回调或可验证签名后，才允许把 `verified=true` 的广告事件写入结算表。客户端回调、广告位名或设备标识本身不能作为生产发奖依据。

## 客户端修复范围

| 发现问题 | 修复原则 |
|---|---|
| 选集广告播放时剧集未暂停 | 展示任何全屏广告前，保存播放状态并调用 `ExoPlayer.pause()`；广告关闭后仅恢复此前正在播放的剧集。 |
| 应用退后台仍播放 | `onStop()` 立即暂停播放器，返回前台不自动播放，需用户单击继续。 |
| 自动下一集与广告并发 | 以单一 `transitionInProgress` 状态串行化：免费下一集自动续播；锁集弹出用户主动确认，广告关闭后写入解锁并请求新播放 URL。 |
| 封面未加载 | 对局域网相对封面 URL 按当前内容服务基地址补全；失败时再使用占位图。 |
| 选集无法滚动 | 在底部弹层中以 `ScrollView` 包裹剧集网格，并限制最大高度。 |
| 屏幕自动熄灭 | 播放界面使用 `FLAG_KEEP_SCREEN_ON`，退出/暂停播放时清除。 |
| 播放错误后拖动不稳定 | Media3 错误时清理状态并展示重试按钮；拖动仅在 `STATE_READY` 或恢复成功后启用。 |
