# JoyeDrama：PostgreSQL 奖励服务与播放器回归测试手册

**适用 APK：`com.dramaflow.app` Debug 测试包**
**适用环境：Windows Docker Desktop + 自有剧内容服务 + PostgreSQL Rewards API + Android 真机**

应用连接两个独立服务，端口不能混用：content service 负责片单、封面、播放会话与内容解锁；Rewards API 负责宝石、钱包、签到、随机宝箱、皇冠、广告事件与广告频控。

| 服务 | 默认端口 | App 设置路径 | 作用 |
|---|---:|---|---|
| 自有短剧内容服务 | `8000` | 我的 → 局域网内容服务 | 片单、封面、分集、播放会话、内容解锁。 |
| PostgreSQL 奖励服务 | `8100` | 我的 → 积分与奖励服务 | 广告账本、宝石、钱包、签到、宝箱、皇冠、插屏规则。 |

## 1. Windows 启动

从仓库的 `services/` 目录统一启动：

```powershell
cd C:\JoyeDrama\services
docker compose up -d --build
Invoke-RestMethod http://localhost:8000/health
Invoke-RestMethod http://localhost:8100/health
```

以管理员 PowerShell 放行 TCP `8000` 和 `8100` 的 Private 网络入站连接。手机和电脑必须使用同一个 Wi-Fi。用 `ipconfig` 找到电脑实际 Wi-Fi/以太网 IPv4，例如 `192.168.1.25`。

## 2. Android 地址设置

在应用中分别填写：

```text
局域网内容服务：http://192.168.1.25:8000
积分与奖励服务：http://192.168.1.25:8100
```

真机不能填写 `127.0.0.1`、`localhost`、电脑名或 VPN 地址。模拟器通常使用 `http://10.0.2.2:8000` 和 `http://10.0.2.2:8100`。

## 3. 广告与奖励验收

Pangle 实际素材、倒计时、关闭行为和填充结果由广告平台下发。应用展示全屏广告前必须暂停 Media3 视频；广告关闭、跳过或无填充后必须恢复用户之前的播放意图。

| 编号 | 操作 | 预期结果 |
|---|---|---|
| R-01 | 打开“奖励”页面 | 显示宝石、钱包余额、可提现余额、预计明日可转入金额、广告加速可额外转入金额、连续签到、随机宝箱和五级皇冠。不得显示“三层资金结构”或十集加奖。 |
| R-02 | 当日未签到时点击“看广告签到” | 请求并完整观看一次激励广告后才完成签到和基础宝石入账。成功后再次打开连续签到弹窗，主操作变为“看广告开宝箱”。 |
| R-03 | 首次点击“看广告领取欢迎奖励” | 只有完整观看一次激励广告后欢迎宝石到账；取消或广告失败时不得发放。 |
| R-04 | 已签到后在弹窗点击“看广告开宝箱” | 请求激励广告；若有库存，随机开启一只宝箱并刷新宝石与库存；若广告完整观看时库存为 0，明确提示没有可开启宝箱。 |
| R-05 | 打开奖励页随机宝箱卡 | 显示可开启库存、每日与追剧来源数量，以及后台配置的随机宝石区间。无库存时点击“继续追剧获得宝箱”必须跳转首页。 |
| R-06 | 完成第 3、6…集有效观看 | 服务端新增 1 只追剧随机宝箱，并弹出带红金宝箱图标和弹跳动画的“恭喜获得 1 个宝箱”提示；选择“立即开启”观看激励广告，选择“继续观看”进入下一集流程。 |
| R-07 | 完整看完任意一集 | 悬浮球累计本集待领取宝石，但宝石余额不自动增加。悬浮球仅在播放器页显示“本集翻倍”，其他页面不显示或不可用。 |
| R-08 | 点击悬浮球“全部领取” | 必须完整观看一次激励广告，再消费该广告授权一次性领取所有待领取宝石。已开启翻倍的分集按双倍结算。 |
| R-09 | 播放任意分集时点击播放器内“本集奖励翻倍” | 不依赖本集是否已经完播或已有待领取宝石。完整观看一次激励广告后显示“本集已翻倍”；分集完成时待领取宝石自动以双倍生成。同一集再次点击只能提示已开启，不能重复发奖。 |
| R-10 | 播放任意分集到第 30 秒 | 按后台开关尝试展示一次剧中插屏；广告结束、跳过或无填充后从原进度继续。重新进入该分集时可重新触发该次播放的一次剧中插屏。 |
| R-11 | 每次拖动进度条并松手 | 每次均按后台开关尝试展示拖拽插屏；广告关闭、跳过或无填充后执行目标跳转并恢复播放。与剧中插屏不互相阻断。 |
| R-12 | 每次调整播放速度 | 每次确认倍速调整均尝试展示一次倍速插屏；广告结束、跳过或无填充后应用新倍速并恢复原播放状态。 |
| R-13 | 播放第 1–3 集 | 免费观看，不提示内容解锁广告。 |
| R-14 | 完播后进入第 4 集及以后，或点选锁集 | 先显示“免费集数已用完”；选择“稍后再看”不请求广告，选择“看激励广告解锁”后必须完整观看激励广告。服务端与内容服务解锁成功后自动播放目标集。 |
| R-15 | 已播放至少 90 秒后暂停 | 若配置 `PANGLE_PAUSE_NATIVE_SLOT_ID` 且有填充，展示原生暂停广告；关闭后视频保持暂停，画面中央必须显示半透明“继续播放”按钮；点击后从原进度继续。无广告位或无填充时也应显示该暂停按钮。 |
| R-16 | 皇冠成长 | 显示当前等级、当前每集宝石倍率、下一等级倍率和成长进度；用户侧不展示内部计算条件。点击“看 2 段广告加快升级”后可连续完成两条激励广告并刷新进度。新手为 `1.00x`，默认皇冠为 `2.00x`；后台调整后仅影响未来新生成的分集奖励。 |
| R-17 | 钱包广告加速 | 始终可点击。显示预计额外转入可提现余额金额（默认按当日基础转入的 20%）；激励广告完成后显示本次转入结果和最新预计明日可转入金额，并始终提供“继续加速”，不得提示“已结算 0 宝石”或次数额度。 |

## 4. 播放器与内容回归

| 编号 | 操作 | 预期结果 |
|---|---|---|
| P-01 | 打开选集 | 选集弹层可上下滚动，所有分集可见。 |
| P-02 | 选中后续锁集 | 在用户确认解锁前不请求广告、不切换播放；广告展示时视频和音频均暂停。 |
| P-03 | 锁集广告关闭后 | content service 解锁成功后自动播放目标集；内容服务临时失败时保留重试机会，不能把分集永久标记为“已请求”。 |
| P-04 | 不触碰屏幕持续观看 | 屏幕保持常亮；暂停、退出播放器或进入后台后恢复系统原有休眠策略。 |
| P-05 | 播放失败后拖动 | 可重新加载本集；播放器未进入 `STATE_READY` 时不得执行无效跳转。 |
| P-06 | 查看剧集列表封面 | JSON 中相对 `posterUrl`/`coverUrl` 经 content service 图片接口解析，局域网媒体目录内的图片可访问。 |
| P-07 | 在第 2 集播放 01:15 后退出播放器，再从“我的 → 继续观看”进入 | 必须恢复到第 2 集约 01:15，而不是从第 1 集重新开始。 |

## 5. 开发与生产边界

开发阶段可使用 `ALLOW_DEBUG_AD_PROOF=true` 接收 Debug APK 的测试广告证明。暂停广告必须使用独立 Pangle Native 广告位 `PANGLE_PAUSE_NATIVE_SLOT_ID`，不能用全屏插屏替代，因为应用需要提供随时返回播放的控制。

生产上架前必须关闭调试证明、部署 Pangle 服务端回调/验签，并配置服务端密钥。客户端不能作为正式奖励到账的唯一依据。钱包当前仅展示余额与资格预检，不创建真实打款，也不承诺提现成功；开放提现前必须接入支付、身份校验、反作弊、审核、风控与客服流程。
