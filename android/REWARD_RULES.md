# DramaFlow 阶段化奖励与提现资格规则

**版本：** 原型规则 v1
**原则：** 所有数额、任务条件、每日上限、资格和到账时限必须在用户操作前可见；当用户满足公示条件时，应进入确定的结算流程。生产环境以服务端签名配置为唯一事实来源。

> 本规则采用“任务进度 + 阶段宝箱 + 资格分层”的促活结构，但不使用不可达目标、隐藏门槛、伪随机进度或虚假提现承诺。

## 奖励结构

| 模块 | 规则 | 用户可见信息 |
| --- | --- | --- |
| 基础任务 | 签到、观看、解锁和通知任务按固定金币奖励结算。 | 每项任务展示目标、当前进度和奖励金额。 |
| 广告双倍 | 仅限标注“可双倍”的任务；完整激励广告回调后奖励翻倍。 | 展示“普通奖励 / 双倍奖励”两个确定数额。 |
| 阶段进度 | 每领取一次有效任务奖励，获得 1 个当日阶段点。 | 展示总点数、已达宝箱、下一宝箱还差的点数。 |
| 阶段宝箱 | 3、6、10 点分别领取固定 60、120、220 金币。 | 奖励数额与条件固定展示，不做隐藏概率。 |
| 每日上限 | 原型每日基础奖励上限为 800 金币；宝箱奖励不计入基础任务上限。 | 在钱包中展示已得、剩余和重置时间。 |
| 金币兑换 | 原型汇率为 1,000 金币 = ¥1.00 资格余额，仅作为演示。 | 真实汇率、手续费、可兑换档位由服务端返回。 |

## 提现资格结构

| 资格条件 | 原型口径 | 业务边界 |
| --- | --- | --- |
| 最低兑换门槛 | 500 金币 | 页面明确显示，不动态提高。 |
| 基础行为条件 | 完成至少 3 集有效观看与 1 次每日签到 | 服务端验证事件，不由客户端伪造。 |
| 每日次数 | 每日最多 1 次申请 | 超限时给出下一次可申请时间。 |
| 状态呈现 | 未达标、可申请、审核中、完成、失败 | 每个状态必须给出确定原因或下一步。 |
| 风控 | 设备、账号、任务完成和广告奖励由服务端核验 | 仅拒绝有明确规则依据的异常请求，并提供申诉/客服入口。 |

## 原型与生产差异

当前 APK 不创建真实余额、不执行兑换、不发起提现。它仅演示资格计算与进度视觉。正式接入时，任务事件、广告回调、阶段宝箱、金币余额、兑换资格与提现状态都必须来自服务端；客户端不保存可结算的最终金额，也不自行决定审核结果。

## 服务端配置建议

生产接口可下发 `dailyBaseCoinLimit`、`milestoneThresholds`、`milestoneRewards`、`conversionRate`、`minimumWithdrawalCoins`、`requiredWatchedEpisodes`、`requiredCheckInDays`、`dailyWithdrawalLimit` 和 `ruleVersion`。客户端只负责展示、收集用户动作与请求结算；服务端负责校验、幂等、审计和实际权益变更。
