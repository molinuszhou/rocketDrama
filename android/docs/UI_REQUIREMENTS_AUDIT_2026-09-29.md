# JoyeDrama UI 文档核对与修复记录

**核对依据：** `JoyeDrama项目Sep23,2026.docx`（2026-09-23）
**完成日期：** 2026-09-29
**范围：** Android 原生界面与多语言文案；不改变奖励服务的账本结算规则。

## 修复清单

| 文档要求 | 处理结果 | 实现位置 |
|---|---|---|
| 金额信息不够突出 | 欢迎奖励、签到当日金额、钱包上限目标分别使用大号、自适应且单行优先的金额排版。 | `RewardLifecycle.kt`、`RewardDashboard.kt`、`WalletScreen.kt` |
| 欢迎奖励信息过多，按钮层级不清楚 | 全屏欢迎页调整为“图标 → 新人奖励标签 → 大金额 → 领取 → 稍后”，保持礼花动画与垂直居中。 | `RewardLifecycle.kt` |
| 新人奖励的 20/200 压缩版面 | 服务端既有策略已是 **600,000 内部单位**（默认市场 US$60）；界面读取服务端兑换值并自适应显示，不写死金额。 | `RewardLifecycle.kt`、`029_v1700_300usd_three_day_curve.sql` |
| 大额目标改为 300，避免旧的多档目标冲突 | 钱包只显示 **US$300 上限路径**、当前差额和“去追剧赚现金”动作；移除旧 $750/$1,200 等目标。 | `WalletScreen.kt` |
| 右侧额外奖励图标与其他区域风格不一致 | 奖励中心的现金、签到、宝箱使用职责明确的 `ic_cash_reward`、`ic_calendar_reward`、`ic_random_chest_reward` 资源。 | `RewardDashboard.kt`、`RewardLifecycle.kt` |
| 今日金额与签到金额重复 | 每日福利仅保留一个突出“今日金额”；签到弹窗不再显示七日总额，改为“今日与后续奖励”。 | `RewardDashboard.kt`、`RewardLifecycle.kt` |
| 签到七天都展示导致金额过小、过密 | 统一签到条仅展示当前节点前后最多 3 天；每个节点使用更大的现金金额与清晰状态。 | `RewardLifecycle.kt` |
| 奖励中心应引导用户到钱包并提示继续看剧 | 奖励中心钱包余额可直达钱包页；钱包页展示剩余差额并提供“去追剧赚现金”动作。 | `RewardDashboard.kt`、`WalletScreen.kt` |
| 首页参考 Coin Drama，内容太重复 | 保留单一高优先级主推海报，去除主推剧在横向推荐架的重复出现，收紧标题、搜索、分类、主推、推荐、全量剧集的节奏。 | `CatalogScreens.kt` |
| 需要补充但不过载的手势引导 | 播放器仅首次显示短提示“轻点暂停 · 上滑下一集”，约 3 秒后自动淡出并记录已展示状态。 | `PlayerScreen.kt` |
| 剧中悬浮奖励图标过高、文字在多语言中易拥挤 | 悬浮入口改为紧凑现金图标和数字标签，下移到控制区上方；不再展示容易溢出的长文案。 | `PlayerScreen.kt`、`RewardEngagement.kt` |
| 点击个人资料中的语言却弹出签到 | 语言设置会消费尚未展示的启动期奖励提示；启动签到保持独立的引导事件，不再作为语言切换的副作用。 | `DramaAppActivity.kt` |

## 验证

- Android Kotlin 已执行 `:app:compileDebugKotlin` 并通过。
- 新增本地化键覆盖 English、Português、Español、Français、Bahasa Indonesia、简体中文与繁體中文。
- 奖励金额、欢迎奖励与钱包目标继续读取服务端快照；客户端只负责展示，未改变服务端结算。

## 发布前真机检查

1. 使用英文、法文和印尼语进入奖励中心，确认三日签到卡与宝箱副标题不截断。
2. 使用 60/90/200 美元钱包快照确认 US$300 进度、差额和大字金额均不换行。
3. 首次进入播放器确认手势提示仅出现一次，悬浮现金入口不遮挡播放器控制栏。
4. 在启动奖励尚未展示时打开“我的 → 语言”，确认只显示语言选择，不弹出签到或欢迎奖励。
